# Forgot Password API Documentation

## Overview

This document describes the forgot password functionality for the Android application. The implementation follows a secure approach where the Android app generates the OTP locally and sends it to the server for SMS delivery.

## Flow Diagram

```
1. User clicks "Forgot Password"
2. User enters mobile number
3. Android app generates 6-digit OTP locally
4. Android app calls /api/forgot-password/send-otp with mobile + OTP
5. Server verifies mobile exists and sends OTP via SMS
6. User enters OTP in Android app
7. Android app verifies OTP locally (no server call needed)
8. User enters new password
9. Android app calls /api/forgot-password/reset with mobile + OTP + new password
10. Server updates password and returns new auth token
```

## API Endpoints

### 1. Send OTP for Forgot Password

**Endpoint:** `POST /api/forgot-password/send-otp`

**Description:** Sends OTP to the provided mobile number for password reset. The Android app generates the OTP locally and sends it to the server for SMS delivery.

**Request Body:**
```json
{
    "phone": "9876543210",
    "otp": "123456"
}
```

**Validation Rules:**
- `phone`: Required, exactly 10 digits
- `otp`: Required, exactly 6 digits

**Success Response (200):**
```json
{
    "status": "success",
    "message": "OTP sent successfully to your mobile number",
    "data": {
        "phone": "9876543210",
        "user_exists": true
    }
}
```

**Error Responses:**

**404 - User not found:**
```json
{
    "status": "error",
    "message": "No account found with this mobile number. Please check the number or register.",
    "requires_registration": true
}
```

**422 - Validation error:**
```json
{
    "status": "error",
    "message": "Invalid input data",
    "errors": {
        "phone": ["The phone field is required."],
        "otp": ["The otp field is required."]
    }
}
```

**500 - SMS sending failed:**
```json
{
    "status": "error",
    "message": "Failed to send OTP. Please try again later."
}
```

### 2. Reset Password

**Endpoint:** `POST /api/forgot-password/reset`

**Description:** Resets the user's password after OTP verification. This endpoint is called after the Android app verifies the OTP locally.

**Request Body:**
```json
{
    "phone": "9876543210",
    "otp": "123456",
    "new_password": "newSecurePassword123"
}
```

**Validation Rules:**
- `phone`: Required, exactly 10 digits
- `otp`: Required, exactly 6 digits
- `new_password`: Required, minimum 6 characters

**Success Response (200):**
```json
{
    "status": "success",
    "message": "Password reset successfully",
    "data": {
        "token": "1|abc123def456...",
        "user": {
            "id": 1,
            "name": "John Doe",
            "email": "john@example.com",
            "phone": "9876543210",
            "role": "customer",
            "is_active": true
        }
    }
}
```

**Error Responses:**

**422 - Invalid OTP:**
```json
{
    "status": "error",
    "message": "Invalid or expired OTP"
}
```

**404 - User not found:**
```json
{
    "status": "error",
    "message": "User not found"
}
```

**422 - Validation error:**
```json
{
    "status": "error",
    "message": "Invalid input data",
    "errors": {
        "new_password": ["The new password field is required."]
    }
}
```

## Security Features

1. **Local OTP Generation**: OTP is generated by the Android app, reducing server-side complexity
2. **SMS Delivery**: OTP is sent via SMS using MSG91 service
3. **OTP Expiry**: OTPs expire after 10 minutes
4. **Token Revocation**: All existing tokens are revoked when password is reset
5. **Audit Trail**: OTP requests are logged in the database for security monitoring
6. **Rate Limiting**: Implement rate limiting on the endpoints to prevent abuse

## Error Handling

### Common Error Scenarios

1. **Invalid Mobile Number**: User enters a mobile number that doesn't exist in the system
2. **SMS Delivery Failure**: Network issues or SMS service problems
3. **OTP Expiry**: User takes too long to enter the OTP
4. **Invalid OTP**: User enters wrong OTP during password reset
5. **Weak Password**: User enters a password that doesn't meet requirements

### Best Practices

1. **User Feedback**: Provide clear error messages to guide users
2. **Retry Mechanism**: Allow users to request new OTP if needed
3. **Loading States**: Show loading indicators during API calls
4. **Input Validation**: Validate inputs on the client side before making API calls
5. **Offline Handling**: Handle network connectivity issues gracefully

## Configuration

### Environment Variables

Make sure these are configured in your `.env` file:

```env
MSG91_AUTH_KEY=your_msg91_auth_key
MSG91_TEMPLATE_ID=your_template_id
MSG91_TEST_MODE=true
```

### SMS Template

Configure your MSG91 template with the following message:

```
Your OTP for password reset is {{otp}}. Valid for 10 minutes. Do not share this OTP with anyone.
```
